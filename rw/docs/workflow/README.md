# Workflow

The canonical human-facing reference for how Ravenswatch RE work happens in this repo. Five chapters, one per technique domain plus a cross-cutting one for facts that span multiple domains. CLAUDE.md is the agent's directive sheet for the same material — when the two need the same rule, the narrative lives here and CLAUDE.md carries a one-line directive that points at the relevant chapter.

## Chapters

| Chapter | What it covers |
|---|---|
| [save-editing.md](save-editing.md) | Save-edit lifecycle, folder taxonomy and naming, CLI primitives, verification recipes, gotchas |
| [frida.md](frida.md) | Frida technique: hook patterns, REPL reference, dump-and-compare, full-process memory snap/diff |

## Doc template (used by every chapter)

Each chapter follows the same five-section shape:

1. **What this is for** — one paragraph. The problem the technique solves.
2. **Concepts** — the small handful of terms a reader needs to understand the rest.
3. **Recipes** — concrete commands with copy-pasteable invocations. The bulk.
4. **Gotchas** — known failure modes and the workaround for each.
5. **Pointers** — links to the relevant findings, tools, and external setup docs.

Findings live in [`../../findings/`](../../findings/) (with [`STATUS.md`](../../findings/STATUS.md) as the manifest). Setup-only docs live elsewhere in the repo; chapters link out rather than duplicating setup steps.

## Cross-cutting process rules

Rules that apply to all RE work in this repo, regardless of which technique you're using.

### Status field

Every doc under `rw/findings/` carries a single `**Status:**` line near the top. Three legal values: `in-progress`, `confirmed`, `archived`. The line MUST match `^\*\*Status:\*\* (in-progress|confirmed|archived)$` exactly — nothing else on the line, nothing extra after the value. The `/findings-status` command greps for that exact pattern and writes [`rw/findings/STATUS.md`](../../findings/STATUS.md).

- `in-progress` — claims not yet independently verified. New findings always start here.
- `confirmed` — claims verified by lab edit, in-game readback, code+test, or independent re-derivation.
- `archived` — superseded or rendered obsolete. Demotion adds a banner; the file stays in place.

Promotion and demotion are one-line edits to the status line. No `git mv`. No directory split. The path stays stable so existing cross-references keep resolving.

### Archive pattern

When a finding is archived, leave the file at `rw/findings/<name>.md` and add a banner near the top explaining what replaced it:

```markdown
> **ARCHIVED YYYY-MM-DD** — superseded by [`<other-finding>.md`](<other-finding>.md).
> Preserved for historical detail (...). Some claims here may be stale or
> contradicted by later work — consult the canonical finding for current facts.
```

The banner is for humans. The `**Status:** archived` line is for the manifest grep. Keep both.

### Status manifest

`rw/findings/STATUS.md` is generated by `/findings-status` (defined at `.claude/commands/findings-status.md`). It greps every finding's `**Status:**` line and rewrites the table sorted by status then filename. Files with zero or multiple matches surface as `?` rows so the inconsistency is visible.

The manifest is a convenience, not a contract. Drift between manifest and individual docs is acceptable; the grep is deterministic so a re-run clears it.

### Doc promotion lifecycle

The full path a finding takes:

1. **Raw analysis** — output goes to `rw/dumps/` (gitignored) while you're working through it.
2. **First writeup** — when there's something worth stating in prose, the `rw-findings-report` skill creates `rw/findings/<slug>.md` with `**Status:** in-progress`. The skill enforces the Sources header and the canonical Status line.
3. **Independent verification** — once the claims hold up to a lab edit, in-game readback, or independent re-derivation, flip the status line to `confirmed`. No move.
4. **Supersession** — when a confirmed finding is replaced, flip the status line to `archived` and add a banner pointing at its successor. The file stays. Cross-references keep working.

Demotion (`confirmed` → `in-progress`) is also fine. Something promoted prematurely just gets its status flipped back.

### Sources header

Every finding doc carries a Sources section with relative paths to the artifacts the analysis was done against. The `rw-findings-report` skill enforces the header on creation; legacy docs that lack it are filled in during overhaul passes (or, when reconstruction is genuinely impossible, marked `Sources: pre-policy — written before the Sources header was mandatory`).

### Backlinks

Every non-README markdown file under `rw/docs/workflow/`, `rw/findings/`, `rw/docs/terminology/`, and `rw/ref/` opens with one line above the H1:

```markdown
[← Back to <parent>](README.md)
```

`<parent>` is the directory's name. The link target is always the directory's own `README.md`. Exceptions: each directory's own `README.md` (no self-link), and `rw/findings/STATUS.md` (regenerated, exempt). Per-save `info.md` files under `rw/saves/**/` are NOT covered — they aren't navigated as a doc tree.
